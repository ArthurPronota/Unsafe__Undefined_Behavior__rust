# Unsafe и Undefined Behavior в Rust

## Что такое `unsafe`

`unsafe` — это **ключевое слово**, которое открывает доступ к **пяти операциям**, которые компилятор **не может проверить** на безопасность. Внутри `unsafe` **ответственность за корректность** ложится на **программиста**.

### Пять вещей, которые разрешает `unsafe`

| # | Что | Пример |
|---|---|---|
| 1 | **Разыменование сырых указателей** | `*const T`, `*mut T` |
| 2 | **Вызов `unsafe` функции/метода** | `unsafe fn dangerous()` |
| 3 | **Доступ к `static mut`** | `static mut COUNTER: i32` |
| 4 | **Реализация `unsafe trait`** | `unsafe impl Danger for T` |
| 5 | **Обращение к `union`** | `union MyUnion { i: i32, f: f32 }` |

### Разбор примера

#### 1. Разыменование сырого указателя

```rust
let mut m = 1;
let rp_m = &mut m as *mut i32;   // &mut i32 → *mut i32

unsafe {
    *rp_m += 1;   // разыменование *mut i32
}
println!("{}", m);   // 2
```

- **Создание** указателя — **без `unsafe`**.
- **Разыменование** (`*rp_m`) — **только в `unsafe`**.

#### 2. Вызов `unsafe` функции

```rust
unsafe fn dangerous_operation(v: *mut i32) {
    *v += 1;
}

unsafe {
    dangerous_operation(rp_m);   // вызов unsafe fn
}
println!("{}", m);   // 3
```

- Функция помечена `unsafe fn`.
- **Вызов** — **только в `unsafe`**.

#### 3. Доступ к `static mut`

```rust
static mut COUNTER: i32 = 1;

unsafe {
    COUNTER += 1;   // чтение + запись static mut
}
println!("{}", unsafe { COUNTER });   // 2
```

- **Любой** доступ к `static mut` — **только в `unsafe`**.
- **`static mut` — опасно** — нет синхронизации, возможны гонки данных.

#### 4. Реализация `unsafe trait`

```rust
unsafe trait Dangerous {
    fn do_it(&self);
}

struct MyStruct;

unsafe impl Dangerous for MyStruct {
    fn do_it(&self) {
        println!("Doing something dangerous!");
    }
}
```

- **`unsafe trait`** — трейт, реализация которого требует **обещаний** от программиста.
- **`unsafe impl`** — программист **гарантирует**, что реализация корректна.
- **Примеры** из std: `Send`, `Sync`, `GlobalAlloc`.

#### 5. Обращение к `union`

```rust
union MyUnion {
    i: i32,
    f: f32,
}

let mut u = MyUnion { i: 1 };
unsafe {
    println!("i: {}", u.i);   // читаем i
    u.f = 10.2;                // пишем f (перезаписывает i)
    println!("f: {}", u.f);   // f: 10.2
}
```

- **`union`** — тип, где **все поля** разделяют **одну** память.
- **Чтение/запись** — **только в `unsafe`**.
- **Опасно:** можно прочитать **неверный** тип.

## Что `unsafe` **не отключает**

**Все остальные проверки** компилятора **работают**:

| Проверка | Работает в `unsafe`? |
|---|---|
| **Заимствование** (borrow checker) | ✅ Да |
| **Типобезопасность** | ✅ Да |
| **Синтаксис** | ✅ Да |
| **Инициализация** переменных | ✅ Да |
| **Проверка `match`** | ✅ Да |
| **Проверка возвращаемых значений** | ✅ Да |

### Пример: borrow checker работает в `unsafe`

```rust
let mut x = 42;
let r1 = &mut x;
unsafe {
    // ❌ всё ещё ошибка: cannot borrow `x` as mutable more than once
    // let r2 = &mut x;
}
```

### `unsafe` **не ускоряет** код

```rust
// Это НЕ быстрее, чем обычный цикл
unsafe {
    for i in 0..1000 {
        // ...
    }
}
```

`unsafe` **не делает** код быстрее **сам по себе**. Он лишь **разрешает** опасные операции.

### `unsafe` **не отключает** borrow checker

```rust
let mut v = vec![1, 2, 3];
let r = &v[0];
v.push(4);   // ❌ ошибка даже без unsafe
```

## Что такое Undefined Behavior (UB)

**UB** — это **поведение**, для которого язык **не даёт никаких гарантий**. Компилятор **вправе**:

- **предполагать**, что UB **не возникает**;
- **оптимизировать** код на основе этого предположения;
- **делать что угодно** — от «работает как ожидалось» до «программа падает» или «выводит мусор».

**UB — это не «ошибка»**, а **нарушение контракта** языка. Программа с UB **некорректна**, даже если «работает» на вашей машине.

## Типичные источники UB в Rust

### 1. Гонка данных через `unsafe`

```rust
static mut COUNTER: i32 = 0;

// Два потока одновременно пишут
unsafe {
    COUNTER += 1;   // ❌ UB: data race
}
```

**Проблема:** нет синхронизации → **data race** → **UB**.

### 2. Висячий сырой указатель

```rust
let p: *const i32;
{
    let x = 42;
    p = &x;
}   // x уничтожен
unsafe {
    println!("{}", *p);   // ❌ UB: use after free
}
```

**Проблема:** указатель указывает на **освобождённую** память.

### 3. Несовместимый алиасинг

```rust
let mut x = 42;
let p1 = &mut x as *mut i32;
let p2 = &x as *const i32;   // ❌ конфликт с p1

unsafe {
    *p1 = 100;
    println!("{}", *p2);   // ❌ UB: aliasing
}
```

**Проблема:** `*mut T` и `*const T` одновременно → **aliasing violation**.

### 4. Чтение неинициализированной памяти

```rust
let x: i32;
let p = &x as *const i32;
unsafe {
    println!("{}", *p);   // ❌ UB: чтение неинициализированной памяти
}
```

**Проблема:** `x` не инициализирован → **мусор**.

### 5. Невалидные значения примитивов

```rust
let b: bool = unsafe { std::mem::transmute(2u8) };   // ❌ UB
```

**Проблема:** `bool` может быть **только `0` или `1`**. `2` — **невалидное** значение.

### 6. Переполнение при арифметике указателей

```rust
let arr = [1, 2, 3];
let p = arr.as_ptr();
unsafe {
    let q = p.add(100);   // ❌ UB: выход за пределы массива
}
```

**Проблема:** указатель **выходит** за пределы массива.

## Почему UB **опасен**

### 1. Компилятор **предполагает**, что UB **не возникает**

```rust
fn foo(x: i32) -> i32 {
    if x > 0 {
        return 1;
    }
    // Компилятор знает: x не может быть UB → оптимизирует
    return 0;
}
```

Если в `unsafe` вы **нарушили** инвариант, компилятор **может** оптимизировать код **неправильно**.

### 2. UB **непредсказуем**

Одна и та же программа с UB может:

- **работать** на вашей машине;
- **падать** на другой;
- **работать** в debug и **падать** в release;
- **работать** сегодня и **падать** завтра.

### 3. UB **не локализован**

UB в **одном** месте может **сломать** программу **в другом** — из-за оптимизаций.

## Как **избежать** UB

### 1. Минимизировать `unsafe`

```rust
// ✅ Безопасно
let v = vec![1, 2, 3];
let sum: i32 = v.iter().sum();

// ❌ Опасно
let p = v.as_ptr();
unsafe { /* ... */ }
```

### 2. Документировать `unsafe`

```rust
/// # Safety
///
/// `p` должен быть валидным указателем на `i32`.
unsafe fn dangerous(p: *mut i32) {
    *p += 1;
}
```

### 3. Использовать безопасные абстракции

```rust
// ✅ Vec, Box, Rc, Arc — безопасны
let v = vec![1, 2, 3];
let b = Box::new(42);
let r = std::rc::Rc::new(42);
let a = std::sync::Arc::new(42);
```

### 4. Использовать `debug_assert!`

```rust
unsafe {
    debug_assert!(!p.is_null(), "pointer must not be null");
    *p += 1;
}
```

### 5. Тестировать с `miri`

```bash
rustup +nightly component add miri
cargo +nightly miri test
```

**Miri** — интерпретатор Rust, который **ловит UB** в `unsafe` коде.

### 6. Использовать `sanitizers`

```bash
RUSTFLAGS="-Z sanitizer=address" cargo +nightly run
```

**AddressSanitizer** ловит **use-after-free**, **buffer overflow** и т.д.

## Итог

### `unsafe`

- **Разрешает 5 операций**: сырые указатели, `unsafe fn`, `static mut`, `unsafe trait`, `union`.
- **Не отключает** borrow checker, типобезопасность, синтаксис.
- **Не ускоряет** код **сам по себе**.
- **Ответственность** за инварианты — **на программисте**.
- **Минимизируйте** `unsafe`, **документируйте** его, **тестируйте** через Miri.

### Undefined Behavior

- **Поведение**, для которого язык **не даёт гарантий**.
- **Компилятор предполагает**, что UB **не возникает** → может **оптимизировать** неправильно.
- **Типичные источники:** гонки данных, висячие указатели, aliasing, неинициализированная память, невалидные значения примитивов, переполнение указателей.
- **Непредсказуем:** работает сегодня — падает завтра.
- **Не локализован:** UB в одном месте ломает программу в другом.
- **Избегайте:** минимизируйте `unsafe`, используйте безопасные абстракции, тестируйте Miri/sanitizers.
- **Правило:** если не уверены — **не пишите `unsafe`**. Если пишете — **документируйте** и **проверяйте**.
